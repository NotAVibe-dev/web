How it works

Five signals, fully sourced, no black box

Every project shows five maintenance signals derived from public data — each with its source, fetch date, and a clear rating. No hidden formula.

Maintenance activity

Substantive releases and merged external PRs over the trailing 90 days. Active, steady, quiet, or dormant.

Responsiveness

Median time to first substantive maintainer response on issues and PRs. Days, weeks, or insufficient data.

Contributor breadth

How many distinct authors are merging code. Broad, narrowing, single-author, or insufficient data.

Security posture

OpenSSF Scorecard-style checks: security policy, CI in place, code review practice. Strong, partial, or none visible.

Get started

Install the MCP server

Give your AI coding assistant grounded, sourced knowledge about open-source project health. Works with Claude, Cursor, Windsurf, VS Code, and any MCP-compatible client.

One command — works with Claude Desktop, Cursor & more
npx @notavibe/mcp

This downloads and runs the notavibe MCP server. Your AI assistant will automatically detect it. No configuration file needed — just run and go.

Install globally via npm
# Install globally npm install -g @notavibe/mcp # Run the server notavibe-mcp

Installing globally makes the notavibe-mcp command available system-wide. Point your MCP client's config at it and you're set.

Add to your MCP client config (e.g. claude_desktop_config.json)
{ "mcpServers": { "notavibe": { "command": "npx", "args": ["@notavibe/mcp"] } } }

Drop this into your client's MCP configuration file. For Claude Desktop, that's ~/Library/Application Support/Claude/claude_desktop_config.json on Mac or %APPDATA%\Claude\claude_desktop_config.json on Windows.
