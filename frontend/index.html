How it works

Five signals, fully sourced, no black box

Every project shows five maintenance signals derived from public data — each with its source, fetch date, and a clear rating. No hidden formula.

Maintenance activity

Substantive releases and merged external PRs over the trailing 90 days. Active, steady, quiet, or dormant.

Responsiveness

Median time to first substantive maintainer response on issues and PRs. Days, weeks, or insufficient data.

Contributor breadth

How many distinct authors are merging code. Broad, narrowing, single-author, or insufficient data.

Security posture

OpenSSF Scorecard-style checks: security policy, CI in place, code review practice. Strong, partial, or none visible.

Get started

Connect the MCP server

Give your AI coding assistant grounded, sourced knowledge about open-source project health. Works with Claude, Cursor, Devin Desktop, VS Code, and any MCP-compatible client.

Server URL — paste into your client's Add MCP server / Connectors setting
https://notavibe.dev/mcp

notavibe is a hosted MCP server, so there is nothing to install and no API key. Add the URL to your client as a remote (HTTP) server.

Run in your terminal
claude mcp add --transport http notavibe https://notavibe.dev/mcp

Adds notavibe to the current project. Add --scope user to make it available in every project.

Add to your MCP client config
{ "mcpServers": { "notavibe": { "type": "http", "url": "https://notavibe.dev/mcp" } } }

Drop this into your client's MCP configuration file. Key names vary by client, so check its MCP docs. A client that only runs local servers can use npx -y mcp-remote https://notavibe.dev/mcp as the command.
